# 质量待办 Web App 设计说明

- 状态：已批准，可进入开发计划与实现
- 日期：2026-10-15
- 工作名称：质量待办
- 目标平台：以 iPhone 主屏幕 Web App 为主，同时兼容桌面浏览器

## 1. 背景

用户是制造企业的质量管理员。当前依赖多张手写便签记录事项，记录中包含编号、时间、箭头关系、圈出的重点、划掉的完成项，以及等待他人回复的事项。主要风险不是无法记录，而是任务分散后难以快速判断：

- 今天必须处理什么；
- 哪些事项已经超期；
- 哪些事项正在等待某个人或部门；
- 何时需要再次跟进；
- 一个问题经过哪些处理，最后如何闭环。

本产品不是通用团队项目管理系统，而是为单个质量管理员设计的轻量闭环工作台。

## 2. 产品目标

第一版需要做到：

1. 任何事项都能在几秒内记录下来；
2. 到达时间节点时，iPhone 能在锁屏和通知中心提醒；
3. 等待他人回复的事项必须有下次跟进时间；
4. 每次状态变化和人工跟进都有记录；
5. 完成或取消后仍可追溯处理过程与结果；
6. 网络中断时仍可查看和编辑，恢复网络后自动同步；
7. 更换手机或清除浏览器数据不会导致云端数据丢失；
8. 在一台轻量 Linux 服务器上稳定运行，不依赖 Docker。

成功标准是：用户每天主要通过“今天”页面工作，能够可靠识别超期、今日到期和等待跟进事项，不再需要依靠散落的纸质便签记忆时间节点。

## 3. 用户与范围

### 3.1 用户模型

- 第一版只有一个固定账户；
- 不开放自助注册；
- 不包含多人分派、团队权限或审批流程；
- 用户首次登录后保持登录，直到主动退出、会话过期或服务器撤销会话。

### 3.2 第一版不包含

- 手写文字 OCR；
- 第三方 AI 服务；
- 企业微信、微信、邮件或日历集成；
- 多人协作、任务分派和审批流；
- 自动生成质量报告；
- 复杂统计仪表盘；
- Word、Excel、PDF 等文档附件；
- 每日、每周、每月之外的复杂重复规则。

## 4. 功能设计

### 4.1 账户与登录

- 使用固定用户名和密码登录；
- 用户名由部署者配置；
- 密码只保存加盐哈希，不保存明文；
- 提供修改密码、退出登录和撤销其他会话的能力；
- 连续登录失败后逐步延长等待时间；
- 登录成功后使用安全、仅 HTTP 可读的 Cookie 维持会话。

### 4.2 任务字段

每个任务包含：

- 标题；
- 详细说明；
- 状态；
- 优先级；
- 截止时间；
- 一个或多个提醒时间；
- 等待对象；
- 下次跟进时间；
- 关联编号或关联信息；
- 多个灵活标签；
- 子任务清单；
- 重复规则；
- 图片附件；
- 可选的完成说明；
- 创建、更新、完成、取消和删除时间；
- 数据版本号。

### 4.3 状态

任务有五种业务状态：

1. 待处理；
2. 进行中；
3. 等待他人；
4. 已完成；
5. 已取消。

业务规则：

- 切换为“等待他人”时，等待对象和下次跟进时间必填；
- 已完成和已取消任务进入历史记录，不直接删除；
- 完成说明为可选字段，避免增加日常操作负担；
- 删除采用软删除，进入回收站 30 天后才永久清理；
- 完成、改期和删除后提供短时间撤销入口。

### 4.4 优先级

优先级固定为：

- 普通；
- 重要；
- 紧急。

排序默认综合考虑超期、优先级和截止时间。超期事项始终优先于尚未到期事项。

### 4.5 标签与查找

- 标签由用户自由创建；
- 一个任务可包含多个标签；
- 标签不替代状态、优先级、等待对象和关联编号等结构化字段；
- 搜索匹配标题、说明、标签、关联编号和等待对象；
- 筛选支持状态、优先级、标签、截止日期和等待对象；
- 第一版使用 SQLite FTS5 建立全文检索索引。

### 4.6 子任务

- 一个任务可以包含任意数量的文本子任务；
- 子任务可独立勾选和恢复；
- 主任务完成时，如果仍有未完成子任务，需要提醒用户确认，但允许继续完成；
- 子任务变化写入处理动态。

### 4.7 重复任务

第一版支持：

- 每日；
- 每周；
- 每月。

每个重复系列包含唯一系列标识。服务器在当前周期到期时生成下一周期任务，并使用“系列标识 + 周期日期”作为幂等约束，避免网络重试或服务重启造成重复任务。

### 4.8 图片附件

- 每个任务最多 6 张图片；
- 图片在 iPhone 端压缩后再上传；
- 最长边缩放到 1920 像素；
- 优先编码为 WebP，不支持时使用 JPEG；
- 编码质量为 75% 至 80%；
- 单张上传文件不得超过 1 MB；
- 上传前展示压缩后的大小；
- 原图不上传，服务器只保存压缩版；
- 单张上传失败可以单独重试，不影响任务文字保存；
- 图片使用随机文件名保存在非公开目录，只能通过已登录的接口读取。

### 4.9 处理动态与追溯

每个任务包含按时间倒序展示的处理动态。系统自动记录：

- 创建任务；
- 修改标题或说明；
- 改期；
- 状态变化；
- 等待对象或跟进时间变化；
- 添加或删除标签；
- 子任务变化；
- 添加或删除图片；
- 完成、取消、删除和恢复。

用户可以手动添加一条简短进展，例如“已电话催办”或“等待检测结果”。系统自动产生的动态不可直接修改，以保证追溯可信度。

### 4.10 通知

- 支持提前提醒和到期提醒；
- 支持每天固定时间发送未完成超期事项汇总；
- 等待他人的任务按下次跟进时间提醒；
- 通知由服务器调度并通过 Web Push 发送；
- 通知只显示任务标题和时间，不在锁屏正文中显示详细说明、关联编号或图片；
- 通知权限被拒绝时，首页显示持续提示，同时保留应用内超期标记；
- 同一提醒使用唯一标识，避免重复发送。

### 4.11 导出、备份和恢复

- 设置页支持导出 CSV，确保可由 Excel 打开；
- 设置页支持导出完整 JSON 数据；
- 服务器每天自动备份 SQLite 数据库和图片目录；
- 备份包含校验清单，恢复时验证数据库记录与图片文件的对应关系；
- 设置页显示最近一次成功备份时间；
- 自动备份失败时写入日志，并在设置页显示明确警告；
- 默认保留最近 14 份每日备份，保留策略可以通过服务器配置修改。

## 5. 信息架构与界面

### 5.1 视觉原则

视觉主题是“冷静、清晰、低干扰”。界面贴近 iOS 的信息层级和触控习惯，但不复制系统应用的商标或私有素材。

- 使用系统字体和动态字号；
- 以列表和分组为主，避免仪表盘式卡片堆叠；
- 仅使用一个主操作色，红色和橙色只表达超期与待跟进；
- 支持浅色、深色、高对比度和减少动态效果；
- 交互目标至少约 44 × 44 CSS 像素；
- 操作按下时立即反馈；
- 底部面板从触发位置相关的方向出现，并可随时关闭；
- 动效使用无明显回弹的短弹簧或淡入，避免干扰工作。

### 5.2 底部导航

底部包含四个入口：

1. 今天；
2. 任务；
3. 日历；
4. 设置。

底栏使用轻量半透明材质。用户启用减少透明度时改为实色背景。

### 5.3 今天

“今天”是默认首页，按以下顺序展示：

1. 同步状态；
2. 已超期、今天到期、等待跟进的数量；
3. 已超期列表；
4. 今天到期列表；
5. 等待跟进列表；
6. 未来七天的临近事项。

任务行直接显示标题、时间和一条最重要的上下文，例如标签、等待对象、关联编号或子任务进度。任务行支持直接完成、打开详情和延期。

### 5.4 任务

- 展示所有任务；
- 顶部提供搜索；
- 提供状态、标签、优先级和日期筛选；
- 默认按风险和截止时间排序；
- 已完成、已取消和回收站是明确的筛选状态，不与当前任务混杂。

### 5.5 日历

- 月视图显示有任务的日期；
- 选择日期后在下方显示当天任务；
- 第一版不实现拖动改期，以减少误操作。

### 5.6 新建与详情

- 右上角加号打开底部新建面板；
- 第一焦点是任务标题，常用字段优先展示；
- 日期、提醒、重复、优先级、标签、子任务和图片按使用频率排列；
- 详情页首先展示状态、标题、截止时间、标签和附件；
- 子任务和处理动态在同一详情页向下排列；
- 完成和取消动作要求明确，但只有永久删除需要二次确认。

## 6. 技术架构

### 6.1 客户端

- React + TypeScript；
- Vite 构建；
- PWA Manifest 和 Service Worker；
- IndexedDB 保存本地缓存与离线操作队列；
- 响应式布局以 iPhone 竖屏为基准；
- 浏览器原生图片解码与 Canvas/OffscreenCanvas 压缩，按实际兼容能力降级；
- Web Push 订阅用于通知。

### 6.2 服务器

- 当前 LTS 版本的 Node.js；
- Fastify 提供 JSON API、认证、上传和推送调度；
- SQLite 保存结构化数据；
- SQLite 使用 WAL 模式；
- 数据库迁移文件随应用版本管理；
- 单个 Node.js 进程由 systemd 启动、守护和重启；
- Nginx 负责 HTTPS、静态文件、压缩、请求体限制和反向代理；
- 服务器不使用 Docker。

### 6.3 持久化目录

建议使用独立、不可被 Nginx 直接访问的目录：

- 数据库：`/var/lib/quality-todo/data/app.db`；
- 图片：`/var/lib/quality-todo/uploads/`；
- 备份：`/var/backups/quality-todo/`；
- 日志：由 systemd journal 管理，必要时额外输出审计与备份日志。

实际路径可通过环境配置覆盖。

### 6.4 主要数据实体

- `users`：固定账户和密码哈希；
- `sessions`：登录会话；
- `tasks`：任务主体、状态、时间、等待对象、关联信息、重复系列和版本号；
- `subtasks`：子任务及排序；
- `tags`：标签；
- `task_tags`：任务与标签关系；
- `reminders`：提醒计划和发送状态；
- `attachments`：图片元数据与存储位置；
- `activities`：处理动态；
- `push_subscriptions`：Web Push 设备订阅；
- `idempotency_keys`：离线重试的幂等请求记录。

## 7. 离线与同步

### 7.1 本地优先交互

用户修改任务时：

1. 客户端先把变化写入 IndexedDB；
2. 界面立即显示结果；
3. 客户端生成唯一操作标识并加入待同步队列；
4. 有网络时发送到服务器；
5. 服务器验证基础版本号并提交数据；
6. 客户端收到确认后移除待同步操作。

### 7.2 冲突

- 每个任务包含递增版本号；
- 更新请求必须携带客户端最后看到的版本；
- 服务器版本已经变化时返回冲突，不采用最后写入者自动覆盖；
- 客户端展示本地版本、服务器版本和修改时间，让用户选择；
- 图片上传和任务文本提交相互独立，单张图片失败不回滚任务文字。

### 7.3 应用更新

- Service Worker 缓存应用外壳，支持离线启动；
- 检测到新版本时不强制刷新正在编辑的页面；
- 没有未保存操作时提示用户更新；
- 数据迁移失败时保留旧缓存和待同步队列，并显示可恢复错误。

## 8. 安全与隐私

- 所有访问必须使用 HTTPS；
- 密码使用 Node.js 内置 `scrypt`、独立随机盐和恒定时间比较；
- 会话令牌使用高强度随机值，数据库只保存令牌哈希；
- Cookie 设置 `Secure`、`HttpOnly` 和 `SameSite=Strict`；
- 修改数据的请求验证来源，并使用 CSRF 防护令牌；
- 登录接口、上传接口和通知订阅接口启用速率限制；
- 所有文本在输出时转义，数据库访问使用参数化查询；
- 图片通过内容签名验证实际格式，不信任文件扩展名；
- Nginx 和应用同时限制上传大小；
- 图片目录不提供静态公开访问；
- 通知正文不包含敏感明细；
- 备份目录限制为应用运维账户可读；
- 不使用第三方分析、广告、OCR 或 AI 服务。

## 9. 异常处理

- 断网：保留本地修改，显示待同步数量，恢复网络后自动重试；
- 登录失效：保留未同步数据，重新登录后继续同步；
- 服务器不可用：继续进入离线模式，不显示空白列表；
- 同步冲突：明确展示两版内容，由用户选择；
- 上传失败：单张独立重试，任务文本正常保存；
- 通知权限被拒绝：提供应用内提示和超期标记；
- 重复任务调度重试：通过幂等约束阻止重复记录；
- 误删：支持短时撤销和 30 天回收站；
- 备份失败：记录原因并展示最近成功时间；
- 时间：服务器保存 UTC，界面默认按 `Asia/Shanghai` 展示和调度。

## 10. 部署与运行

服务器需要：

- Linux；
- Nginx；
- 当前 LTS Node.js；
- systemd；
- 有效域名与 HTTPS 证书；
- 足够存放 SQLite、压缩图片和至少 14 份备份的磁盘空间。

部署流程：

1. 建立专用低权限系统用户；
2. 安装生产依赖并构建前端；
3. 初始化数据库和固定账户；
4. 配置只允许应用账户访问的数据目录；
5. 配置 systemd 服务；
6. 配置 Nginx HTTPS 和反向代理；
7. 配置每日备份计时器；
8. 完成备份恢复演练后投入使用。

## 11. 测试与验收

### 11.1 自动化测试

- 任务状态转换和“等待他人”字段校验；
- 优先级和超期排序；
- 每日、每周、每月重复规则及幂等生成；
- 提醒调度和时区换算；
- 图片格式识别、压缩限制和鉴权读取；
- 登录、会话、CSRF、限流和退出；
- 任务、标签、子任务、活动和附件 API；
- 离线操作重放和版本冲突；
- CSV、JSON 导出；
- 数据库与图片备份恢复。

### 11.2 端到端验收

1. iPhone Safari 添加到主屏幕后可独立打开；
2. 新增、编辑、完成、取消和恢复任务均正常；
3. 断网新增任务，恢复网络后只同步一次；
4. 截止提醒、提前提醒和超期汇总准确送达；
5. “等待他人”必须填写等待对象和跟进时间；
6. 周期任务不重复、不漏生成；
7. 六张图片能够压缩、上传、查看和删除；
8. 搜索可匹配标题、标签、关联编号和等待对象；
9. CSV 可由 Excel 正确打开，JSON 可完整导入恢复；
10. 数据库和图片从备份恢复后保持对应关系；
11. 浅色、深色、大字体、减少动态和减少透明度模式可用；
12. 登录、限流、附件权限和常见恶意输入通过安全检查；
13. 服务器重启后应用、通知调度和同步均自动恢复；
14. 当前编辑过程中部署新版本不会丢失输入。

## 12. 后续扩展边界

第一版稳定使用后，可以独立评估以下方向：

- 手写便签 OCR 与人工确认；
- 任务模板；
- 多人协作和权限；
- 企业微信或邮件提醒；
- 质量问题统计；
- 自动生成周报、月报和闭环报告；
- 更多附件类型。

这些功能不进入第一版，避免增加数据安全风险和部署复杂度。
